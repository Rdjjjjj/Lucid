# Lucid 产品架构

- 版本：0.1
- 日期：2026-10-17
- 状态：已根据《产品设计方案》整理

## 1. 这份文档解决什么问题

Lucid 不是只有一个输入框。它由输入法、设置 App、AI 服务和建议卡片共同组成。

这份文档只说明三件事：

1. Lucid 有哪些产品部分；
2. 每个部分负责什么；
3. 用户输入一句话后，各部分如何配合。

它不规定 Rust、Swift、Windows TSF 或具体代码结构。那些内容属于技术方案。

## 2. Lucid 的产品组成

```text
用户
 │
 ▼
Lucid 输入法 ────── 当前应用的文本框
 │
 ├── 句子处理
 ├── AI 建议
 └── 建议卡片

Lucid 设置 App
 ├── 配置 AI 服务
 ├── 配置模型和 API Key
 └── 引导用户启用输入法
```

双语伴学和中文翻转是输入法提供的辅助能力，不是另一套输入法，也不改变主流程。

## 3. 各部分负责什么

### 3.1 Lucid 输入法

输入法是用户日常使用 Lucid 的入口，负责：

- 接收用户输入的英文字符；
- 让字符立即出现在当前文本框；
- 识别句末标点；
- 把当前完成的句子交给句子处理部分；
- 在用户确认后替换原文；
- 遵守当前应用原有的回车行为。

输入法不负责：

- 自己猜测英文单词；
- 自动替换文字；
- 自动发送聊天消息；
- 保存用户输入历史。

### 3.2 句子处理

句子处理是 Lucid 的核心判断部分，负责：

- 知道当前正在处理哪一个句子；
- 判断句子是否已经由句末标点完成；
- 记录这句话当时的内容；
- 请求 AI 后判断结果是否仍然对应原文；
- 在用户切换输入框或继续修改后让旧建议失效。

它不负责绘制界面，也不直接操作某个具体应用的文本框。

### 3.3 AI 服务连接

AI 服务连接负责：

- 使用用户配置的服务地址、协议、模型和 API Key；
- 发送当前完成的句子；
- 读取 AI 返回的建议；
- 将结果整理成 Lucid 能展示的主建议和修改说明。

它不决定用户是否接受建议，也不直接替换文本。

### 3.4 建议卡片

建议卡片负责把 AI 结果交给用户，提供：

- 修改后的英文句子；
- 替换；
- 保留原文；
- 查看修改。

建议卡片只属于产生它的输入框和句子。输入框失去焦点、原文发生变化或新的请求产生后，旧卡片就不能继续使用。

### 3.5 设置 App

设置 App 负责：

- 配置 AI 服务地址；
- 选择 OpenAI 兼容或 Anthropic 兼容协议；
- 配置模型；
- 保存和清除 API Key；
- 引导用户启用 Lucid 输入法；
- 开关双语伴学和中文翻转辅助能力。

设置 App 不负责日常输入，也不保存输入历史。

### 3.6 双语伴学和中文翻转

这部分是辅助能力，负责帮助用户理解英文内容或查看中文结果。

它必须遵守：

- 不把 Lucid 变成中文输入法；
- 不自动改写英文原文；
- 不自动发送消息；
- 不把中文结果当作下一次英文处理的输入；
- 不干扰替换确认流程。

## 4. 用户输入一句话时的流程

```text
用户输入英文
  ↓
英文立即显示在当前应用
  ↓
用户输入句末标点
  ↓
Lucid 记录当前完整句子
  ↓
AI 服务处理句子
  ↓
建议卡片显示一条主建议
  ↓
用户选择“替换”或“保留原文”
  ↓
替换原文，或结束本次处理
```

用户输入过程中，Lucid 不应该等待 AI，也不应该把正在输入的文字藏起来。

## 5. 建议什么时候有效

一条建议必须同时满足以下条件才可以替换：

- 仍然是原来的应用；
- 仍然是原来的输入框；
- 原文仍然存在；
- 原文没有被用户改动；
- 这条建议仍然是最新请求的结果；
- 用户明确点击或使用快捷键确认。

只要其中一项不满足，建议就失效并隐藏，原文保持不变。

### 示例：用户继续输入

```text
用户输入：I want mai.
Lucid 开始请求 AI。
用户继续输入：coffee.
```

此时前一个请求针对的是旧文本，旧结果不能再替换原文。

### 示例：用户切换窗口

```text
用户在聊天软件输入句子。
AI 正在处理。
用户切换到浏览器。
```

原聊天窗口的建议立即失效，不能显示到浏览器，也不能在浏览器里替换文字。

## 6. 聊天软件中的回车

Lucid 不接管聊天软件的回车行为：

- 用户输入句末标点时，Lucid 可以请求 AI；
- 用户直接按回车时，聊天软件按照自己的规则发送；
- Lucid 不拦截回车；
- Lucid 不自动发送消息。

因此，用户如果希望发送前先获得建议，需要先输入句末标点。

## 7. macOS 和 Windows 的共同规则

首版先完成 macOS。Windows 后续加入时，平台界面和系统接口可以不同，但下面的产品行为必须保持一致：

- 英文字符立即进入当前文本框；
- 拼音可以作为英文单词占位；
- 句末标点触发 AI；
- AI 只给建议；
- 用户确认后才替换；
- 不自动替换；
- 不自动发送；
- 旧建议在文本变化或焦点切换后失效；
- 密码框和安全输入框不处理；
- 不保存输入历史。

macOS 和 Windows 可以使用各自符合系统习惯的建议展示方式，但不能改变这些行为。

## 8. 产品边界

Lucid 首版包含：

- macOS 系统级英文输入法；
- 设置 App；
- 用户自己的 AI 服务配置；
- 句末标点触发的 AI 建议；
- 建议替换和保留原文；
- 双语伴学和中文翻转辅助能力。

Lucid 首版不包含：

- 中文输入法；
- 中文候选词库；
- 整句中文翻译输入；
- 自动改写；
- 自动发送；
- 输入历史；
- 账号和云同步；
- 课程、单词本和学习统计。

## 9. 这份架构对后续工作的约束

后续设计和实现都应遵守以下判断：

- 新功能不能改变用户确认后才替换的原则；
- 平台差异不能改变 Lucid 的核心输入流程；
- AI 服务不能直接决定是否修改用户文本；
- 建议界面不能绕过有效性检查；
- 设置 App 不能读取或建立输入历史；
- 双语辅助功能不能逐步演变成中文输入法。
